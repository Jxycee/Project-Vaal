# E2E speed (2026-10-08)

Goal: cut the ~1355s mobile suite by about a third without deleting a test.
Estimates below are from the architect's plan and are NOT measured. Confirm by
summing the `After Hooks` afterAll step durations in the next `results.json`.

## Landed on chore/e2e-speed

1. Cleanup through one PostgREST call (~140s). `cleanupTestBuilds(mode)` in
   `e2e/helpers.ts` no longer walks the UI (card, settings, Delete, Confirm, per
   row, in a fresh browser context, about 40 times per run). It reads the bearer
   from `e2e/.auth/user.json`, sends `DELETE /rest/v1/builds?user_id=eq.<sub>&name=like.E2E-*`
   (plus `name=not.like.E2E-SHARED-*` in `spec` mode), asserts 200/204, then reads
   back with the same filter and asserts nothing matched. RLS policy "Owners can
   do everything with their builds" (cmd ALL) permits it; build_checkpoints
   cascades. `cleanupWithFreshPage(browser)` keeps its signature (browser now
   unused), so no spec changes. `auth.setup.ts` calls `cleanupTestBuilds('sweep')`,
   which also removes `E2E-SHARED-` rows. The UI delete path is still asserted
   deliberately by build-settings.spec.ts and scratch-planner.spec.ts.
   `SHARED_PREFIX` is exported for the shared-fixture change below.
2. Mobile project at `deviceScaleFactor: 1` (~90s, unmeasured, could be 30-150s).
   Pixi renders at devicePixelRatio on software WebGL every frame. Viewport,
   isMobile, hasTouch and UA stay Pixel 7. A/B it: run checkpoints.spec.ts alone
   twice with and without the override; revert the one line if the gain is under 5%.
3. Wider warm-up in `auth.setup.ts` (~15s): also GETs `/builds/<unknown token>`,
   the same with `?tab=gear`, `/login` and `/` in the existing parallel batch,
   asserting status < 500. Writes nothing.

## Deferred (need a Playwright run to verify)

4. Seed through `createBuildViaApi` in build-persistence test 2 and build-page-edit
   test 1 (~35s, medium risk: pruning of unconnected allocations on load).
5. Worker-scoped shared fixture build for read-only specs (~30s, medium risk).
   Name it `E2E-SHARED-fixture-<ts>`; change 1's `spec` mode already skips that
   prefix, so the cleanup side is ready. Specs that mutate the default fixture
   must keep their own import (gear, skills, checkpoints, checkpoint-duplicate,
   reader-export, scratch-planner, pob-export, ggg-build-export, config-panel,
   derived-stats, desktop-layout).
6. Merge same-URL read-only tests into test.step blocks (~15s, skip if unsure).

## Controller notes

- Do not add workers: shared account, account-wide cleanup, one dev port.
- A cheaper tree-ready wait is not a lever; the cost is the 5.1 MB fetch +
  normalise + the render loop that change 2 attacks.
- The two FAILED tests in the baseline (build-page deep link 66s, pob-import
  59.5s) are timeout time; fix separately.
- The storageState access token is fixed for the run. A suite longer than the
  JWT lifetime (default 1h) would make cleanup fail loudly with a 401 rather
  than leak silently.
