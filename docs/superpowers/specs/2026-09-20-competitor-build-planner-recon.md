# Competitor Build Planner Recon

Date: 2026-09-20
Scope: hands-on testing of the leading Path of Exile 2 (and one Diablo 4) build-planning tools, at desktop width and at a 375x812 mobile viewport, to inform Project Vaal's build planner (mobile-first, PS5/Xbox console players browsing on phones).

## Method (what you actually did per site, and what you could not reach)

For each reachable site I opened it in the browser pane, declined/closed any consent or promo overlays, and tried to actually build something: pick a class, allocate passive nodes, open the gear/equipment UI and equip an item in a slot, open the skill/gem UI and socket a skill plus a support. I then re-ran the same page at a 375px-wide mobile viewport and repeated the equip/socket attempt to see what breaks. No accounts were created and nothing was downloaded.

- **Maxroll.gg** — reached both the standalone Passive Tree tool (`/poe2/passive-tree`) and the full PoE2 Planner (`/poe2/planner`). Selected Warrior, used the node search to highlight "life" nodes, attempted direct node clicks (see caveats below), equipped a helmet (Imperial Greathelm) through the item picker, edited its rarity/affixes, added a skill (Dread Banner) and socketed a support gem (Armour Demolisher) into it, and scrolled through the full page to confirm the Atlas Tree and Ascendancy panels. Tested at 375px width for the standalone tree and the full planner.
- **Mobalytics.gg** — reached the PoE2 hub and a live featured build guide ("Twister Gemling Legionnaire"). There is no interactive gear/tree planner of Mobalytics' own for PoE2; build guides embed a plain-text **Path of Building export code** with a "Copy Code" button and rely on the reader pasting it into the desktop PoB app or a third-party viewer. Confirmed this is the pattern (not an oversight) by checking the page for any embedded tree/gear widget — there is none. Tested article reflow at 375px.
- **pobb.in** — the homepage is just a paste box (no build to inspect without a real share code). Rather than fabricate a code, I found two real public PoE2 pobb.in links via a general web search (`https://pobb.in/TUsV2f6hi8cg`, `https://pobb.in/HlipAJFWM6Mi`) and opened one to inspect the actual shared-build viewer at both desktop and 375px width.
- **poeplanner.com** — reached the PoE1 planner (v2.10.8.3). Selected a class, opened Passive Tree/Equipment/Skills/Stats/Config/Notes/Import-Export tabs, opened an equipment slot's replace popover, used the Skills tab to add a gem to a new link group and assigned that link group to a gear slot. Note: the browser pane reported "You are offline — account related features will not work," which appears to be a sandboxing artifact of this test environment, not a claim about the live site; where this affected what I could observe (e.g., the item-search-by-name box returned no results), I've flagged it rather than asserting the feature is broken. Tested at 375px width.
- **poe2skilltree.com** — unreachable as a planning tool: it resolves to a parked ad-directory page ("Directory Index") with generic link cards, not a real tree tool. Not tested further per the two-tries rule.
- **poe2wiki.net** — reached (after an initial bot-check interstitial cleared itself). This is the official community wiki (MediaWiki), hosted by GGG. Its "Passive Skill Tree" page is a text/encyclopedia article with no embedded interactive tree widget. Recorded as a genuine finding (no tool here), not treated as a planner.
- **d4builds.gg** (bonus, non-PoE) — reached the Diablo 4 Build Planner. Selected a Warlock, opened the Helm item picker (Aspects & Uniques list and Item Stats tab), opened the Skill Tree tab and inspected a node tooltip. Tested the same flows at 375px width.
- Not attempted: poeplanner's actual passive-tree allocation on PoE2 (site is PoE1-only, as the task's target list itself notes), and pob.cool (a third-party web port of PoB surfaced incidentally via pobb.in's "Open in web" link) — out of scope for the assigned target list, noted only in passing below.

Caveat on precision: Maxroll's and PoE Planner's passive trees render at a scale where individual node hit-targets are only a few pixels wide on both desktop and mobile screenshots; several of my own coordinate-based clicks on unlabeled nodes did not register an allocation. I'm reporting this as a directly observed difficulty of the interaction model (tiny click/tap targets), not asserting the sites are non-functional — allocation clearly does work in principle (the search-highlight feature and the "0/125" counters are both live and responsive to other inputs).

## Per-site findings

### Maxroll.gg — Passive Tree tool + PoE2 Planner

**Layout.** The standalone tree tool is a single embedded widget on an otherwise ordinary article page: header (class/ascendancy/patch dropdowns, allocated/ascendancy/lab point counters, search box), then the tree canvas, with a fullscreen-expand control. The full Planner (`/poe2/planner`) is one very long vertical scroll: header controls (class, ascendancy, GGG import/export, "Import from PoE2 Account," "Import from PoB," profile save/load) → Equipment (paper-doll) side-by-side with Skills (gem-link list) → per-section Notes fields → Gem Cutting Order → Skill Rotations → Pros/Cons → Passive Tree (same widget as the standalone tool, embedded) → Atlas Tree (a second, even larger tree, ~375 points) → Ascendancy panel. Every major section has its own collapse toggle, but there is no tabbed navigation between them — it's all one page.

**Function.** Items are picked via a modal with a left category tree (by armor/defense type) and a right scrollable list of base types; selecting one jumps straight into an "Edit" view with name/base/rarity/item level/quality/corrupted/sanctified fields and separate Enchant/Fractured/Explicit/Crafted affix sections, each with an "Add Mod" picker, a socket count, and even a "GGG Build Planner" min-level + rich-text notes field (this ties into GGG's own in-game build-notes feature). Skills are socketed by clicking a skill slot (opens an icon-grid picker with authentic in-game tooltips), then clicking one of the empty support-gem circles next to it (up to 5, matching PoE2's max support count) to open a second, level-tiered picker. Selected skill+supports render as a small labelled tree in the Skills panel. Weapon loadouts are handled via Set 1/2/3 tabs above the paper doll. There is no live DPS or stat-total readout anywhere in the planner — it is a build **documentation and sharing** tool (character sheet + notes + native GGG import/export + PoB import), not a damage calculator.

**Mobile reality check at 375px.** The standalone tree page is broken on first load: below the header there is a large blank gap (roughly 300px) where the tree canvas should be, and a floating autoplaying video ad sits on top of the content. Scrolling past the gap reveals the toolbar (Patch/Class/Ascendancy dropdowns) horizontally clipped — the third dropdown is cut off at the viewport edge — and the tree itself renders at maybe 300px square with node dots only a few pixels across. Tapping "fullscreen" does not hide the page header or the ad; it just expands the widget within the remaining space, and a sticky ad banner permanently occupies roughly 15% of viewport height even in "fullscreen." Double-tap did not zoom the canvas. In the full Planner, the equipment paper-doll itself reflows reasonably (a sensible single-column, portrait character-sheet arrangement), and the item **edit** form (name/rarity/affixes) reflows to a clean single column — but the item **picker/browse** modal does not adapt at all: it keeps the desktop two-pane layout (category tree + item list) squeezed into 375px, so item names are truncated mid-word ("Massive Mitt...", "Sirensc Gloves"). The support-gem picker is the same story: usable in principle, but every list/category column is desktop-width logic simply shrunk.

**Tech tells.** The tree is canvas/WebGL rendered — the accessibility tree exposes no per-node structure at all (confirmed via `read_page`; the entire widget is opaque `img`/`generic` refs), so it is not screen-reader- or DOM-inspectable, and node hit-testing is purely pixel-based. Search-and-highlight (typing "life" lights up every matching node in green across the whole tree) is a genuinely well-built feature layered on top of that canvas. State appears to be server-saved profiles ("My Profiles," "Save") plus native GGG build-file import/export and PoB import — not a pure URL-encoded state.

### Mobalytics.gg — PoE2 hub and build guides

**Layout.** Standard content-hub layout: nav tabs for Meta Builds / Guides / Tier Lists / Classes, a builds listing page, and individual build pages that are long-form guide articles (hero card with class/ascendancy tags, "Track Build," "Focus Mode," a collapsible table of contents, then prose sections).

**Function.** There is no in-house interactive tree/gear/gem planner for PoE2. A build's actual configuration is exposed as a **Path of Building export string** in a text box with a "Copy Code" button — the guide tells the reader to paste it into the desktop PoB app (there is no in-page viewer at all, unlike pobb.in). The site's real differentiator is the "Live Build Tracker" / "Live Seasonal Characters" feature, which connects to a creator's actual live PoE2 character (via "Connect My Account") to show real-time gear/level, and the written guide content itself (strengths/weaknesses, leveling videos, farming strategies, vendor-recognition regex strings for loot filtering).

**Mobile at 375px.** Reflows cleanly, because there's fundamentally little to reflow — it's an article. Long paragraphs, a collapsible table of contents, and the PoB code box (not tested for wrapping behavior in depth, but text content generally is mobile-safe on this template). No interactive planner UI exists to break.

**Tech tells.** No tree/gear widget, canvas or otherwise. The "build" is fundamentally a portable PoB text blob plus prose; Mobalytics' value-add is content and account-linked live tracking, not planning UI.

### pobb.in — PoE Building share-code viewer

**Layout.** A single scrolling page per shared build: header stat line (Life, Energy Shield, Mana, effective HP, per-element max hit, four resistances, DPS, attack/cast speed, hit chance, active config mods) plus the raw share-code text box with Copy/Web/Open buttons, then a Loadout dropdown (the build author can save multiple named level checkpoints, e.g. "Level 31 – Empezamos con Balista," "Level 63 – 3a Ascendencia"), then Gear (paper-doll-style item icons), Gems (named link groups such as "Habilidad Principal"/main skill, "Spirit Gems," "Extra Dano," each a colour-coded skill+supports list), a static Tree Preview image, and a free-text Notes section the build author writes.

**Function.** This is a **read-only** viewer, not an editor — there is no way to allocate, equip, or socket anything here. "Web" opens the code in `pob.cool` (a third-party web port of the actual PoB calculator) and "Open" launches the code in the desktop PoB app via a `pob2://` protocol link. The loadout dropdown lets a reader step through a character's leveling history, which is a nice touch for leveling guides. The site's only interactive input is the homepage's paste-a-PoB-code-and-get-a-link flow.

**Mobile at 375px.** This is the best mobile experience among the PoE sites, precisely because it has nothing to interact with: everything is static text and images, so it stacks into a clean single column — full-width Copy/Web/Open buttons, a legibly-sized stat block, a gear grid that wraps naturally, and a Tree Preview image that shrinks to fit (unreadable at the node level, but that's fine since it's illustrative only, not something you're expected to click). The Notes section (plain monospace-ish text with hand-typed section banners) is fully readable.

**Tech tells.** The tree preview is a static rendered image, not an interactive canvas — there is nothing to click, so there's nothing to break. State lives entirely in the PoB share-code string (`https://pobb.in/<id>` resolves to a stored blob of that opaque code); the site is a thin read-only wrapper plus deep links out to the real editors (desktop PoB, pob.cool).

### poeplanner.com — PoE1 planner (referenced for mature gear/gem UX)

**Layout.** A proper tabbed single-page-app: Passive Tree / Equipment / Skills / Stats / Config / Notes / Import-Export as persistent top tabs (not an infinite scroll like Maxroll). Equipment is a classic paper-doll silhouette with a Weapon Set 1/2 toggle and an "Edit mode" switch. Skills is a completely separate concept from Equipment here: it's a list of "Link Groups" (an abstraction of a socketed item, e.g. "6-link") each independently assignable to a conceptual gear slot (Weapon/Offhand/Helmet/Body/etc. via a dropdown) rather than clicking sockets drawn on the item art itself — plus a persistent live Life/Mana **reservation** meter at the top of the Skills tab that updates as you add reservation/aura skills.

**Function.** Clicking an equipped slot opens a small "Replace: `<slot>` / With:" popover (fixed-size, not a full picker on click — a menu icon has to be tapped first). The right-hand "Build Items" panel is a personal library search (searches items *you've already created for this build*, not a global catalog), which is a different mental model from Maxroll's "browse the whole base-type catalog" approach. Skills/gems are added via "+ Add gem," which opens a searchable, **tag-filterable** list (rows show gem name plus mechanic tags like Aura/Critical/Spell/AoE, with the icon on the right) — a genuinely different and arguably more scannable pattern than Maxroll's icon-only grid. Each gem row has inline Level/Quality number fields and an enable checkbox.

**Mobile at 375px.** The top tab bar does not reflow into anything mobile-native — it becomes a horizontally-clipped strip ("‹ E / EQUIPMENT / SKILLS / ST ›") that requires tapping small chevrons to reach Passive Tree, Stats, Config, Notes, and Import/Export, which are pushed off-screen. The equipment paper-doll is not resized for touch — it's the same small rectangular slot grid as desktop, and tapping a slot reveals the same tiny fixed-width "Replace" popover seen on desktop, not a full-screen sheet. Large banner/video ads (World of Tanks, HBO Max) are inserted directly in the content flow between panels, each roughly as tall as the paper-doll itself.

**Tech tells.** The passive tree (not deeply tested here since PoE1 tree isn't the assigned target) renders similarly to Maxroll's — a dense web with small click targets. The gear/gem system is clearly its own custom SPA state (weapon sets, link groups, per-build item library) rather than a thin wrapper around a share code; there's an explicit offline/account-required distinction ("You are offline — account related features will not work"), implying save/sync is account-backed for at least some features while local editing works without login.

### d4builds.gg — Diablo 4 Build Planner (bonus, non-PoE mobile reference)

**Layout.** Tabs across the top: Gear & Skills / Skill Tree / Paragon / Mercenaries / War Plans / Notes. Gear & Skills shows equipment as **labelled rows** (icon + slot name + status, e.g. "Helm — Empty") arranged left/right around a central skill dial, rather than a literal paper-doll silhouette.

**Function.** Tapping a gear row opens a **centered modal** with a search box, a segmented "Aspects & Uniques" vs "Item Stats" toggle, and a single-column scrollable results list (icon, name, rarity label, favorite star) — noticeably simpler and more scannable than the two-pane category-tree pickers on the PoE sites. "Item Stats" exposes affixes as four dropdown selectors plus a Tempering slot and a Transfigure toggle — because D4's affix pool is fixed per slot, this avoids PoE's free-text mod search entirely. The Skill Tree tab shows a smaller, segmented tree (not one giant circular web), a live "Remaining: N" points counter, a skill search box, and — notably — a "Leveling Path" toggle that records allocation order for a leveling guide as a built-in feature rather than a manual notes field.

**Mobile at 375px.** This was the strongest mobile adaptation observed in this whole survey. The top tab bar becomes a 3x2 icon grid instead of a clipped scroll strip — every section stays one tap away with no hidden overflow. Equipment rows become full-width, ~64px-tall tap targets with clear icon/label/status. Tapping a row opens the **same centered single-column modal** as desktop, just full-width — not a cramped shrink of a two-pane layout. It still carries the same intrusive autoplaying video ad pattern as every other ad-supported site here, floating over roughly a quarter of the screen.

**Tech tells.** Skill tree nodes are clearly DOM/SVG-ish discrete elements with tooltips triggered on first tap (a second tap allocates), not a raw canvas blob — node hit targets were large enough that tooltips landed reliably, unlike the PoE trees.

## Cross-site patterns — what everyone does the same way, and why

- **Paper-doll or slot-list + side/below skill panel.** Every tool (Maxroll, poeplanner, d4builds, and implicitly pobb.in's read-only rendering) separates "what's equipped" from "what's socketed/linked" into two adjacent regions. This mirrors the in-game character sheet and is what players already expect from years of ARPG UI convention — it is not GGG-specific chrome, just a layout convention (equipment grid + skill list), so adopting the *pattern* does not touch the "no GGG art as template" rule.
- **Category/tag filtering beats free scrolling once catalogs get large.** Maxroll (category tree), poeplanner (mechanic tags), and d4builds (Aspects vs Stats toggle + search) all converge on some form of filtered/searchable list rather than a flat scroll, because PoE-scale item and gem catalogs are too large to browse linearly.
- **A picker opens as a modal/overlay, not inline editing.** Nobody lets you edit an equipped item in place on the paper doll; every site pops a separate surface (modal, popover, or drawer) to browse and confirm a choice, then returns you to the sheet.
- **Sharing is text-code based, not just a URL.** PoE's whole ecosystem (Maxroll's GGG export, PoB codes on Mobalytics, pobb.in) converges on copy-pasteable opaque codes as the portable unit of a build, with sites layering read-only viewers or editors on top. This is bigger than any one competitor — it's the format the PoE community already trades builds in.
- **Ad monetization actively degrades every one of these tools.** Every single site tested — Maxroll, Mobalytics, poeplanner, d4builds — inserted autoplaying video ads that overlap content, and on mobile these ads claim a disproportionate share of an already-small viewport. This is a real, observed, cross-site weakness, not a hypothetical.

## Where they are all weak on mobile

This is the sharpest and most consistent finding across the whole survey:

1. **Interactive pickers are desktop layouts, shrunk — not redesigned.** Maxroll's and poeplanner's item/gem picker modals keep their two-pane (category list + results list) desktop structure at 375px, producing truncated item names and cramped touch targets. d4builds is the one clear exception: its picker becomes a genuine full-width single-column list on mobile. This is the single most copyable/avoidable failure mode we observed.
2. **Passive trees are canvas-rendered pixel art with no touch affordances.** Maxroll's tree (and, by inspection, poeplanner's) exposes zero DOM structure for individual nodes — everything is hit-tested by raw pixel coordinates. At 375px the whole tree can render inside a space smaller than 350x350px with node dots a few pixels wide; there is no evidence of pinch-zoom, double-tap-zoom, or any mobile-specific interaction layer. This is the hardest problem in the whole space and the one where "make it work on a phone" is a genuine, unsolved design problem for every competitor.
3. **Primary navigation gets clipped instead of adapted.** poeplanner's seven-tab bar becomes a horizontally-scrolling strip with only ~3 tabs visible and small chevron arrows to see the rest, permanently hiding sections (Passive Tree, Config, Notes, Import/Export) unless the user notices the chevrons. Maxroll avoids this by not having tabs at all (everything is one long scroll instead), which sidesteps the clipping problem but creates a different one: you must scroll past enormous embedded widgets (a full tree, then a full Atlas tree) to reach sections below them.
4. **Ads eat a disproportionate share of a small screen.** A sticky bottom banner or a floating autoplay video routinely claims 15-25% of a 375x812 viewport on every ad-supported competitor tested, on top of already-cramped controls. On desktop the same ad is a rounding error; on mobile it is often as tall as the functional UI it sits next to.
5. **Nothing broke down all the way to unusable except one specific case:** Maxroll's standalone tree tool had an outright rendering failure on first mobile load (a large blank gap where the canvas should be, requiring a scroll-and-wait before content appeared) with an ad overlapping it during that gap. That is a genuine, reproducible defect, not just a design compromise.

## Recommendations for Project Vaal

**(a) Patterns worth adopting — genuine conventions users already expect**

- Keep the paper-doll-or-labelled-slot-list next to a skill/gem panel; players coming from any of these tools (and from the game itself) already read a build through that lens. *Rationale:* every competitor converges on this independently — it's not one site's idiosyncrasy, it's the shared mental model of "character sheet."
- Make the item/gem picker a single-column, full-width, search-first list on mobile, the way d4builds does — not a shrunk two-pane category browser. *Rationale:* directly observed as the difference between a usable mobile picker (d4builds) and a broken one (Maxroll, poeplanner).
- Offer a tag/mechanic filter (à la poeplanner's Aura/Spell/AoE pills) in addition to plain text search once the wiki's gem/skill catalog is large enough that scrolling alone is impractical. *Rationale:* poeplanner's tag rows were more scannable in our test than Maxroll's icon-only grid for anyone who doesn't already recognize every gem icon on sight.
- Support a portable share/import code as a first-class feature, since the constraint file already scopes wiki icons and tree sprites to real game-data use — a share string is just data, not art, so it's fully compatible with that rule. *Rationale:* the entire PoE competitive landscape (Maxroll GGG-format export, PoB codes, pobb.in) already treats a copy-pasteable code as the unit of a shareable build; players will expect Project Vaal builds to be similarly portable.
- Record allocation/leveling order as a structured feature (d4builds' "Leveling Path" toggle), not a free-text notes field. *Rationale:* every PoE tool we saw handles "what order do I level this in" via manual prose notes; d4builds treats it as data the tool itself tracks, which is strictly more useful and something we can do better from day one.

**(b) Things to deliberately do differently for mobile**

- Do not render the passive tree as an opaque canvas/WebGL blob with no per-node DOM structure. Build node hit-targets as real, individually addressable elements (even if visually rendered with GGG's sanctioned tree-export sprites per the repo's art rule) so we can give them touch-friendly effective hit areas larger than their visual size, and so search/filter highlighting and accessibility both work. *Rationale:* this is the single largest, most consistently observed mobile failure across every competitor tree we tested — nobody has solved it, which is exactly the opening to differentiate.
- Design the primary section navigation (tree / gear / skills / stats) as a mobile-native pattern — bottom tab bar or a 2-row icon grid like d4builds — rather than either an infinite single-page scroll (Maxroll) or a horizontally-clipped tab strip (poeplanner). *Rationale:* directly contrasts the two failure modes we saw (endless scroll vs. clipped tabs) against d4builds' icon-grid approach, which was the only one that kept every section reachable in one tap on a 375px screen.
- Treat pinch/double-tap zoom and pan on the tree as a first-class, tested interaction from the start, not an afterthought bolted onto a desktop canvas. *Rationale:* none of the PoE tools showed any evidence of mobile-specific zoom handling; ours can be the first that does.
- Keep the ad-free/low-chrome budget disciplined on mobile specifically — no autoplaying video, no sticky banner that claims a fixed percentage of viewport height regardless of screen size. *Rationale:* every ad-supported competitor loses 15-25% of a 375x812 screen to ads at some point in the flow; since Project Vaal isn't ad-funded the same way, this is a free, immediate advantage if we simply don't reproduce the problem.
- Make the read-only "view a shared build" experience (think pobb.in) deliberately simple and static-first, since that was the one mobile experience in this whole survey that worked well without any special effort — resist the temptation to make the shared-build view as interactively heavy as the editor. *Rationale:* pobb.in's mobile page was the best one we tested, and it got there by having almost nothing interactive to break.

**(c) Explicit non-goals / traps**

- Do not copy Maxroll's "everything on one infinitely long page" layout for the full planner. It technically works but forces mobile users to scroll past two full tree widgets (passive + atlas) to reach sections below them; a tabbed or collapsible-by-default structure serves mobile far better.
- Do not build a personal "item library you search within" as the primary gearing flow (poeplanner's "Build Items" pattern) unless we also offer a global catalog browse — in our test this model was confusing on first contact because it wasn't obvious you had to create an item before you could "find" it.
- Do not use GGG artwork, chrome, or layout skinning as a shortcut to look "authentic" — per the repo's art-use rule, GGG art is reserved strictly for depicting real game content (tree sprites, wiki icons, currency icons from live game data), never as a template for our own UI chrome or decorative elements. Every recommendation above is about interaction pattern and information architecture, not visual skin, specifically so it stays compatible with that constraint.
- Do not assume a desktop-first build (any of the PoE tools we tested) will "just work" if squeezed at the end. Every mobile failure we documented came from a layout that was designed desktop-first and reflowed afterward; Project Vaal's own mobile-first rule is directly validated by this recon, not just a stylistic preference.

## Open questions for the human

- How deep does Project Vaal's own passive tree need to go for v1 — full interactive allocation with respec, or a lighter "recommended path" viewer first (closer to pobb.in's read-only tree, which was easy to get right) before committing to solving the hard canvas/touch problem?
- Should Project Vaal support importing an existing PoB or GGG build-export code on day one (to meet players where their current sharing habits already are), or is that a fast-follow once our own planner and share format exist?
- Do we want a live DPS/stat calculator (something none of the PoE-specific tools we tested actually provide — Maxroll explicitly does not calculate DPS, it just documents the build)? That would be a meaningful differentiator but is a large scope increase; worth a separate scoping pass before committing.
- Given every competitor's ad-driven mobile degradation, what is Project Vaal's own monetization plan, and can we commit now to never sacrificing mobile viewport space to it — since that commitment is itself one of our clearest competitive angles?
