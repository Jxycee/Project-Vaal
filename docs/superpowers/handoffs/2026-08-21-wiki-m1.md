## Three decisions only Jaycee can make

These were deliberately NOT guessed at or auto-resolved. Nothing blocks on them technically — the branch works either way — but each has real consequences:

### 1. AGENTS.md's GGG-art guardrail doesn't exist

The plan (and my own design spec) assumed `AGENTS.md` already contained a "GGG art is a scoped exception, limited to the tree" guardrail that Task 7 would generalize to cover wiki icons too. **It doesn't exist.** Verified via `git log --follow -- AGENTS.md`: the file has exactly one commit, and it's never contained this text. The guardrail language I quoted throughout the design spec actually came from an unrelated draft file (`Downloads\CLAUDE.md`) that was never adopted into this repo — a conflation I made early in the session and only caught when Task 7's implementer refused to invent policy text unilaterally.

This branch now ships 184MB→36MB of GGG-sourced item/gem icon art with **no written policy anywhere in the repo** governing GGG-art use. Options:
- Write the guardrail into `AGENTS.md` now (a real policy decision — I can draft language once you tell me what the rule should actually say).
- Decide the tree's existing precedent is self-evidently sufficient and skip it.

### 2. Which file is the actual product plan doc?

The original wiki plan's Task 7 called for editing `poe2-console-hub-plan.md` (§4 source correction, §12 decisions, §13 open items). No file exists at that path. The closest match is `docs/superpowers/plans/poe2-console-hub-plan7_12_2026.md` — a dated file that still says `poewiki.net` (should be `poe2wiki.net`, or now, arguably neither, since the source changed to poe2-toolkit entirely) and still lists Wiki as "Not yet built." I didn't touch it — wrong-file risk on a document meant to be the single source of truth felt worse than leaving it stale one more session.

### 3. Should `/data/wiki/**` also sit behind the auth gate?

`/wiki` (the UI) is correctly gated per D1. But `src/proxy.ts`'s matcher excludes `data/`, so the raw JSON and icons are publicly fetchable by URL even though the page isn't. The final review flagged this as "worth a conscious decision, not an accident" — it's game data, not user data, so it's not a security hole, but it's a real architecture choice with a knock-on effect: **Important finding #8** (browse pages re-parsing the full index server-side on every request instead of the browser fetching the static file directly) was deliberately left unfixed because its correct fix depends on this answer. Settling this unblocks that cleanup too.

## Known, accepted residual (non-blocking)

`resetIconRoot()` in `scripts/sync-wiki.ts` wipes the whole icon tree once, up front, before any of the three kinds' truncation guards run. If a future sync's `syncItems` or `syncSkills` step (not just `syncMods`) trips the guard and throws, the icons are already gone but the old JSON isn't — a locally broken intermediate state. Doesn't reach production (a failed sync step blocks the CI workflow's PR-creation step), recoverable locally via `git checkout -- public/data/wiki`. Worth a follow-up before the guard fires in anger for real.

## Real bugs found and fixed along the way (not scope changes, just noting for context)

- `WIKI_PATCH_VERSION` was stale on arrival in Task 1 (404'd against the live CDN) — fixed via a live patch-server handshake, documented in the recon doc.
- The truncation guard (`previousCount`/`findPreviousVersionDir`) was inert in its original form — inherited from my own plan's sample code, not an implementer mistake — fixed twice (once at task-review, once more thoroughly at final review) and now has live confirmation it actually fires.
- Real gem-name slug collisions (Herald of Ash/Ice/Thunder, per-weapon default attacks, 45 unreleased "Coming Soon" placeholders) needed a `dedupeSlug` helper not in the original plan.
- 13,354 of 16,679 raw mod entries had no display name (internal ids like `UniqueAttackCriticalStrikeChance1UNUSED`) — filtered.
- Icons: full-resolution (up to 512×1024, 759KB) served in a 48px box — downscaled to ≤128px, cut icon payload from 184.5MB to ~36MB.
- Service worker was precaching all 27,771 wiki data files (211MB) for every visitor to any page — excluded.
- 211MB was being traced into each of the three detail-page serverless functions — icon downscale fixes the actual deploy-blocking size regardless of platform; the `next.config.ts` trace-excludes are additionally correct but unverifiable from this Windows machine (confirmed via direct picomatch testing) and will only show their full effect on a real Vercel/Linux build.
